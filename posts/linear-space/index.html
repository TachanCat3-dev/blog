线性空间与 sRGB：为什么颜色总是偏暗

2026 年 10 月 12 日 · 渲染 · 色彩

把一张在 Photoshop 里调好的贴图放进引擎，光照一打，中间调明显发暗。这不是错觉，而是颜色空间在某个环节错位了。

问题出在哪#

绝大多数 8 位图片存的是 sRGB 编码的值，它并不等于真实的光强。显示器为了照顾人眼的非线性感知，会把线性亮度“压”成人眼更舒服的编码；而渲染里的加法、乘法、插值，却都要求光照在线性空间里进行。

如果把 sRGB 数值直接拿去参与光照计算，中间调的光就少了一大截：编码值 0.5 对应的线性亮度只有约 0.214。

正确的链路#

在渲染管线里，顺序大致是这样：

  1. 采样颜色贴图时，把 sRGB 编码解码成线性值（DCC 里给贴图标记 sRGB，或在采样后手动解码）
  2. 在线性空间里做光照、混合、插值
  3. 色调映射之后，再把线性结果编码回 sRGB 交给显示器

只有颜色数据需要解码。金属度、粗糙度这类“数据贴图”本身就是线性数值，不要再套一次 gamma。

一个近似#

离线渲染常用 2.2 次幂做近似，实时管线里更常见的做法是让硬件采样器直接完成转换。手写的时候，至少要保证两个方向是配对的：

float3 ToLinear(float3 c)
{
    return pow(c, 2.2);
}

float3 ToSRGB(float3 c)
{
    return pow(c, 1.0 / 2.2);
}

一些对照#

sRGB 编码值线性值说明
0.00.0黑
0.250.051暗部压缩得更厉害
0.50.214最常见的中间调陷阱
0.750.522亮部差异变小
1.01.0白

整条链路都放在线性空间里之后，画面通常会比“直接拿贴图算”更亮。但更重要的是，混合和插值不会再出现脏边。

小结#

  • 颜色贴图要解码，数据贴图保持线性
  • 光照、混合、插值都在线性空间里做
  • 输出前记得编码回 sRGB
  • 遇到颜色偏暗，先检查贴图设置，再检查后处理链
